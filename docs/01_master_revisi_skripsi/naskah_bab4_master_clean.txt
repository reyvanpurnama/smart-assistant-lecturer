Berikut adalah potongan kode sumber (source code) implementasi cleansing teks pada middleware:

Listing 4.1 Fungsi Pembersihan Teks (Text Cleansing)
// Location: src/lib/grading/text-parser.ts
export function cleanRawStudentAnswer(rawText: string): string {
  if (!rawText) return "";
  
  return rawText
    // 1. Normalisasi karakter newline dan carriage return
    .replace(/\r\n/g, "\n")
    // 2. Hilangkan non-printable control characters
    .replace(/[\x00-\x09\x0B\x0C\x0E-\x1F\x7F]/g, "")
    // 3. Pangkas spasi horizontal berlebih (multiple spaces menjadi single space)
    .replace(/[ \t]+/g, " ")
    // 4. Batasi newline beruntun maksimal 2 baris (mencegah bloated prompt)
    .replace(/\n{3,}/g, "\n\n")
    .trim();
}

    4.2.2. Sub-Modul Prompt Assembler & Knowledge Grounding
Sub-modul ini mengimplementasikan struktur prompt modular (Gambar 3.3) dengan menyatukan instruksi kaku, parameter rubrik dari dosen pengampu, materi referensi grounding, serta jawaban mahasiswa yang telah dibersihkan ke dalam format instruksi terstruktur sebelum dikirimkan ke model LLM.

Potongan kode sumber perakitan prompt modular pada middleware ditunjukkan sebagai berikut:

Listing 4.2 Prompt Assembler & Knowledge Grounding
// Location: src/lib/grading/prompt-composer.ts
export function composeGradingPrompt(input: ComposePromptInput): string {
  // 1. Format parameter rubrik dosen menjadi daftar terstruktur
  const rubricBlock = input.rubrics
    .map((r, i) => `${i + 1}. Aspect: ${r.aspect}\n   Weight: ${r.weight}%\n   Criteria: ${r.description}`)
    .join("\n\n");

  // 2. Rakit struktur prompt modular (Role, Task, Grounding, Input Data, Output Format)
  return [
    "### [ROLE]",
    "You are a strict but fair smart assistant lecturer for essay and pseudocode grading.",
    "",
    "### [TASK]",
    "Evaluate the student's answer using a step-by-step Chain-of-Thought (CoT) strategy:",
    "1. Analyze the student's answer logic relative to the essay question, rubrics, and reference material.",
    "2. Compare the logic of the student's answer with the context grounding. Note any discrepancies.",
    "3. Reason about each specific grading aspect in the rubrics and assign scores strictly on a 0-100 scale.",
    "4. Determine the overall holistic score and provide feedback based on this step-by-step reasoning.",
    "",
    "### Area Context Grounding (Lecturer Authority)",
    "#### [CRITERIA] Rubrik Penilaian:",
    rubricBlock,
    "",
    "#### [CONTEXT] Konteks Akademik / Materi Referensi:",
    input.contextGrounding,
    "",
    "#### [SOAL_ESAI] Soal Ujian:",
    input.soalEsai,
    "",
    "### [INPUT_DATA] Jawaban Mahasiswa:",
    input.studentAnswer,
    "",
    "### [OUTPUT_FORMAT]",
    "You MUST respond ONLY with a valid JSON object matching the schema below...",
    '{"holistic": {"score": number, "feedback": "string"}, "rubric": [...], "weighted_total": number, "global_reasoning": "string"}'
  ].join("\n");
}

    4.2.3. Sub-Modul Orchestrator & Groq API Client
Sub-modul ini mengelola komunikasi asynchronous ke layanan inferensi Groq API Cloud, menerima respons teks JSON dari model GPT-OSS 120B, melakukan parsing JSON, serta menghitung total nilai terbobot (weighted total) sesuai aturan kebijakan penilaian.

Potongan kode sumber pengolahan inferensi dan eksekusi pada middleware API route:

Listing 4.3 Orchestrator & Groq API Execution Route
// Location: src/app/api/grade/route.ts (Potongan Logika Utama Orchestrator)
export async function POST(req: NextRequest) {
  const { submissionId } = await req.json();
  const supabase = createAdminClient();

  // A. Ambil Data Jawaban, Tugas, dan Rubrik dari Supabase
  const { data: submission } = await supabase.from("submissions").select("*").eq("id", submissionId).single();
  const { data: assignment } = await supabase.from("assignments").select("*").eq("id", submission.assignment_id).single();
  const { data: rubrics } = await supabase.from("rubrics").select("*").eq("assignment_id", assignment.id);

  // B. Rakit Prompt Modular via Sub-Modul Assembler
  const prompt = composeGradingPrompt({
    soalEsai: assignment.question,
    contextGrounding: assignment.reference_context,
    studentAnswer: submission.raw_answer_text,
    rubrics: rubrics.map(r => ({ aspect: r.aspect_name, weight: r.weight, description: r.description }))
  });

  // C. Eksekusi Inferensi API ke Groq Cloud (Model GPT-OSS 120B)
  const provider = getLLMProvider({ providerName: "groq", modelName: assignment.model });
  const rawLLMOutput = await provider.generateCompletion({ prompt, temperature: 0.1 });

  // D. Parsing Respons JSON & Rekonsiliasi Skor
  const parsedResponse = parseLLMResponse(rawLLMOutput);
  const finalWeightedScore = computeWeightedTotal(parsedResponse.rubric);

  // E. Simpan Log Hasil Evaluasi ke Basis Data Supabase
  await supabase.from("submissions").update({ holistic_score: finalWeightedScore, global_reasoning: parsedResponse.global_reasoning, status: "graded" }).eq("id", submissionId);

  return NextResponse.json({ success: true, finalScore: finalWeightedScore });
}

    4.4. Analisis Statistik dan Keandalan AI
Sub-bab ini merupakan pusat analisis kuantitatif utama yang membuktikan keandalan dan tingkat keselarasan penilaian otomatis Smart Assistant Lecturer terhadap penilaian manual dosen (ground truth). Pengujian dilakukan secara menyeluruh terhadap 33 dokumen jawaban mahasiswa Kelas IF23A.

    4.4.1. Landasan Rumus & Perhitungan Step-by-Step Kendall's Tau (τ)
Koefisien Korelasi Kendall's Tau (τ) digunakan untuk mengevaluasi apakah AI memiliki logika hirarki peringkat yang sama dengan dosen dalam menentukan jawaban mana yang relatif lebih baik atau lebih buruk. Persamaan baku Kendall's Tau-b didefinisikan sebagai:

   τ = (P - Q) / sqrt( (P + Q + T_x) * (P + Q + T_y) )

Keterangan Variabel:
- P (Concordant Pairs) : Jumlah pasangan sampel di mana hirarki nilai dosen dan AI sejalan (x_i > x_j dan y_i > y_j).
- Q (Discordant Pairs) : Jumlah pasangan sampel di mana hirarki nilai dosen dan AI berlawanan (x_i > x_j tetapi y_i < y_j).
- T_x : Jumlah kembar (ties) pada skor AI.
- T_y : Jumlah kembar (ties) pada skor Dosen.
- N : Jumlah total sampel mahasiswa (N = 33).

Rincian Komputasi Step-by-Step pada Dataset 33 Mahasiswa (Iterasi 2):
a. Jumlah Total Pasangan Kombinasi = N * (N - 1) / 2 = 33 * 32 / 2 = 528 pasangan.
b. Dari 528 pasangan tersebut, diperoleh:
   - Pasangan Concordant (P) = 379 pasangan.
   - Pasangan Discordant (Q) = 28 pasangan.
   - Ties pada Skor AI (T_x) = 71 pasangan.
   - Ties pada Skor Dosen (T_y) = 25 pasangan.
c. Pembilang (P - Q) = 379 - 28 = 351.
d. Penyebut = sqrt( (379 + 28 + 71) * (379 + 28 + 25) ) = sqrt( 478 * 432 ) = sqrt( 206496 ) ≈ 454.42.
e. Maka Nilai Kendall's Tau (τ) = 351 / 454.42 = 0.7724.

Nilai Kendall's Tau sebesar τ = 0.7724 (dengan p-value = 1.24e-08 < 0.05) mengindikasikan tingkat keselarasan peringkat yang sangat kuat dan signifikan secara statistik. Hal ini membuktikan bahwa logika penalaran model GPT-OSS 120B mampu meniru urutan prioritas penilaian dosen secara konsisten.

    4.4.2. Landasan Rumus & Perhitungan Step-by-Step Mean Absolute Error (MAE)
Mean Absolute Error (MAE) digunakan untuk mengukur rata-rata besarnya selisih mutlak antara skor prediksi AI (y_i) terhadap skor aktual dosen (x_i) tanpa memperhitungkan arah kesalahan. Rumus baku MAE didefinisikan sebagai:

   MAE = (1 / N) * Σ |x_i - y_i|

Keterangan Variabel:
- N : Jumlah total sampel jawaban mahasiswa (N = 33).
- x_i : Skor asli manual dari dosen pengampu (ground truth) pada sampel ke-i.
- y_i : Skor prediksi otomatis yang dikeluarkan oleh sistem AI pada sampel ke-i.
- |x_i - y_i| : Nilai mutlak selisih skor antara dosen dan AI pada sampel ke-i.

Rincian Komputasi Step-by-Step pada Total 33 Sampel (Iterasi 2):
a. Setiap selisih skor mutlak antara Dosen dan AI dihitung per mahasiswa (|x_i - y_i|).
b. Total akumulasi seluruh selisih mutlak 33 mahasiswa di basis data Supabase diperoleh sebesar 179.85 poin.
c. Maka Nilai MAE = 179.85 / 33 = 5.45 poin.

Perhitungan ini membuktikan bahwa pada Iterasi 2, rata-rata deviasi fisik skor AI terhadap ground truth dosen hanya sebesar 5.45 poin (turun drastis sebesar -70.3% dibanding Iterasi 1 sebesar 18.33 poin).

# Location: scratch/colab_analisis_sal.py
import csv, math

def calculate_kendall_tau(x, y):
    n = len(x)
    nc = nd = tx = ty = 0
    for i in range(n):
        for j in range(i + 1, n):
            dx = x[i] - x[j]
            dy = y[i] - y[j]
            prod = dx * dy
            if prod > 0: nc += 1
            elif prod < 0: nd += 1
            else:
                if dx == 0 and dy != 0: tx += 1
                elif dy == 0 and dx != 0: ty += 1
    return (nc - nd) / math.sqrt((nc + nd + tx) * (nc + nd + ty))

def calculate_mae(x, y):
    return sum(abs(a - d) for a, d in zip(x, y)) / len(x)

AI secara ketat menilai query SQL berdasarkan skema database universitas dan kriteria 10 aspek yang telah dikunci di Supabase.

    4.5.2. Pembahasan Dampak Chain-of-Thought (CoT)
Penerapan instruksi CoT pada elemen [TASK] memaksa AI untuk menyusun penalaran bertahap (global_reasoning) terlebih dahulu sebelum mengeluarkan angka skor. Perubahan signifikan terjadi antara Iterasi 1 dan Iterasi 2:
a) Pada Iterasi 1 (Binary Scoring), tanpa CoT yang luwes, AI mengevaluasi skor secara kaku. Kesalahan tipografi minor (seperti lupa tanda petik tunggal pada string NIM) langsung diberi skor 0, yang mengakibatkan deviasi kesalahan skor sangat tinggi (MAE = 18.33 poin).
b) Pada Iterasi 2 (3-Point Partial Credit + CoT), middleware memaksa AI menganalisis tingkat kebenaran logika parsial. Ketika menemukan kesalahan minor, penalaran CoT AI mengenali bahwa struktur logika query utama sudah benar, sehingga AI memberikan skor parsial (skor 50). Hal ini secara langsung berhasil memangkas kesalahan fisik skor hingga -70.3% (MAE turun dari 18.33 poin menjadi 5.45 poin) dan meningkatkan keselarasan peringkat sebesar +75.5% (Kendall's Tau naik dari 0.4400 menjadi 0.7724).
